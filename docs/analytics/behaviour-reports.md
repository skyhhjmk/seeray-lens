# Page behaviour reports

The collector stores a bounded, control-character-cleaned page title beside the sanitized page path. Daily page-title counts are rebuilt from `raw_event` into `analytics_page_title_daily`; entry and exit page paths and titles are rebuilt into each `analytics_session`. The raw event stream remains the source of truth.

`GET /api/v1/sites/{siteId}/analytics/page-titles` reports page views by title and path. `GET /api/v1/sites/{siteId}/analytics/entry-exit` reports visits by entry and exit page. `GET /api/v1/sites/{siteId}/analytics/user-flow` reports ordered page transitions for up to five steps. All three accept the selected date range and optional saved `segmentId`; page-title views use the business date of each page-view event, while entry/exit and user-flow reports select sessions by their start date and include the full session journey. This avoids labeling a period boundary as a real session exit.

The user-flow report orders page views inside each session by normalized event time, receive time, and ingest ID. Each edge contains `step`, `sourcePath`, `sourceTitle`, `targetPath`, `targetTitle`, and `sessions`. A null target represents a session that ended on the source page. The report groups repeated journeys, keeps the 100 most common edges per step, and applies the same saved audience segment as the rest of the selected site's reports. In the Behaviour UI, operators can switch steps, filter by starting page, and select a destination to follow it into the next step. Each edge also offers a transition sample view: `GET /api/v1/sites/{siteId}/analytics/user-flow/samples` returns pages of at most 20 matching anonymous sessions with their first six page views, using the selected date range and optional saved segment. The opaque `nextCursor` can be sent as `cursor` to load the next page. It does not return visitor IDs or event payloads. The report counts transitions, not unique people.

The Behaviour report presents page titles, entry pages, exit pages, site-search terms, content performance, Web Vitals, tracked event types, and the user-flow explorer in separate panels. Download and outlink events are included when their tracker options are enabled. Titles not supplied by older tracker versions appear as “Untitled page” or without a title in the API. Site search requires explicit tracker integration; see [site search analytics](site-search.md). Content reports aggregate explicitly marked impressions and interactions by name, piece and target; see [content analytics](content-tracking.md). Web Vitals collection is opt-in and reports LCP, INP and CLS overall and by page; see [Web Vitals](web-vitals.md). Form and media reports are separate opt-in views under Behaviour; they expose only stable explicit IDs and aggregate playback/form events, never media URLs or field values. See [media analytics](media-analytics.md) for the two-part opt-in and playback milestone semantics. Page overlays are not implemented yet.
